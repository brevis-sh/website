# Deploying brevis.sh

The site is static HTML, generated by `build.py` and committed. Cloudflare Pages
serves it; there is no server-side anything, no secrets and no environment
variables (the generator reads none).

## Cloudflare Pages, connected to Git

One Pages project, connected to `brevis-sh/website`:

| setting | value |
|---|---|
| production branch | `master` |
| build command | `python3 build.py --dist` |
| build output directory | `dist` |
| root directory | `/` |

Every push to `master` deploys; every other branch and pull request gets a
preview URL. `brevis.sh` is a custom domain on the project.

Why a build command at all, when the HTML is committed: not to produce the HTML,
which is already in the repo (`build.py --check` in CI proves it is current),
but to produce **`dist/`**, which holds only what is served. No `build.py`, no
`templates/`, no `content/*.md`: a `.md` served next to the `.html` generated
from it is a second indexable copy of every page.

Pages reads two files from the output as they are: `_headers` (cache and
security headers) and `_redirects`. It serves `404.html` with status 404 for an
unmatched path on its own.

## What ships

`_headers` sets a CSP that allows exactly what the site uses: its own scripts,
one inline snippet (the `.js` class), the Google Fonts stylesheet, the font
files, and one `GET` to `api.github.com` (`js/stars.js`, the star count in the
header's button). Nothing else: no analytics, no frames, no form posts. If you
add analytics, that header is the file to change; forgetting it means the script
is blocked silently in the browser console.

## Checking a deploy

```bash
curl -sI https://brevis.sh/            | grep -i 'cache-control\|content-type'
curl -sI https://brevis.sh/css/styles.css | grep -i cache-control   # immutable
curl -so /dev/null -w '%{http_code}\n' https://brevis.sh/docs/cli/   # 200
curl -so /dev/null -w '%{http_code}\n' https://brevis.sh/nothing     # 404
curl -sI https://brevis.sh/github      | grep -i location            # the repo
curl -s  https://brevis.sh/brevis/sdk/?go-get=1 | grep go-import     # go get
```

After a content change, check `/sitemap.xml`: a missing URL means a page was
generated but not linked.

## Moving from the old Worker

`brevis.sh` used to be a custom domain on a Cloudflare Worker named `brevis`,
built from `AreteAcademy/brevis` with root directory `site`. To move it: create
the Pages project, confirm the preview URL serves the site, remove the custom
domain from the Worker, add it to the Pages project, then delete the Worker.
